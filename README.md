# TipsToTreat

Home remedies, health tips, and recipes from one Indian kitchen. A single-author site with a public front and an author-only admin panel.

## Stack

- TanStack Start + TanStack Router, React 19, TanStack Query (SSR-integrated via `@tanstack/react-router-ssr-query`)
- Tailwind v4, shadcn (base-nova), lucide icons, Khand + Mukta fonts (Devanagari support)
- Cloudflare Workers + D1, Drizzle ORM v1 (`drizzle-orm@rc`, `drizzle-kit@rc`)
- better-auth (email + password, single author) and Tiptap v3 for the editor

## Local development

```bash
pnpm install
cp .dev.vars.example .dev.vars     # then set a real BETTER_AUTH_SECRET (openssl rand -base64 32)
pnpm db:migrate:local
pnpm db:seed:local                 # optional synthetic sample entries (src/content/samples.ts)
pnpm dev
```

Set `AUTHOR_EMAIL` in `.dev.vars`, then create that account at `http://localhost:5173/sign-up` (password or Google). It gets the better-auth admin role and sees the author panel at `/admin`. Everyone else who signs up is a reader who can like entries and comment. Without `AUTHOR_EMAIL`, the first account created becomes the author (dev convenience only).

### Google sign-in

An OAuth web client already exists in the Google Cloud project (client id in `wrangler.jsonc`). Put its secret in `.dev.vars` as `GOOGLE_CLIENT_SECRET`; the Google button appears automatically once both values are set. Authorised redirect URIs must include `<origin>/api/auth/callback/google` for every origin you use (localhost, workers.dev, custom domain). While the OAuth app is in testing mode only the test users listed under Google Auth Platform › Audience can sign in with Google.

## Database

- Schema: `src/lib/db/schema.ts`. Migrations are generated by drizzle-kit into `drizzle/` and mirrored as flat SQL into `migrations/` for wrangler.
- Caution: when drizzle-kit rewrites a table (`__new_table` pattern), D1 ignores `PRAGMA foreign_keys=OFF`, so rows in tables that reference it with `ON DELETE CASCADE` are deleted. Rebuilding `user` wipes sessions, accounts, likes and comments. Prefer additive changes on tables with dependents, or back up first.
- `pnpm db:generate` → generate a migration from schema changes.
- `pnpm db:migrate:local` / `pnpm db:migrate:remote` → apply with wrangler.
- `pnpm db:seed:local` / `pnpm db:seed:remote` → load the sample entries. They are synthetic; delete them from the admin panel before launch.

## Deploy

```bash
npx wrangler secret put BETTER_AUTH_SECRET
npx wrangler secret put GOOGLE_CLIENT_SECRET
pnpm db:migrate:remote
pnpm deploy
```

Set `AUTHOR_EMAIL` in `wrangler.jsonc` before the author signs up on production.

## Content and SEO

- Entry notes are Markdown (Tiptap with the Markdown extension in the editor); the server renders sanitized HTML on save.
- Every entry is also served as Markdown at `/<kind>/<slug>.md`, linked from the page with `rel="alternate"`.
- `/sitemap.xml`, `/llms.txt`, `/robots.txt`, canonical links, Open Graph tags, and schema.org JSON-LD (Recipe, HowTo, Article, WebSite).

`BETTER_AUTH_URL` is optional. Left blank (the default in `wrangler.jsonc`), better-auth derives the origin from each request, so version previews and the workers.dev URL both work. Set it to the canonical domain only if you want auth redirects pinned there.

## Layout

- `src/routes/_site/*` public pages (home, `/$kind`, `/$kind/$slug`, `/search`)
- `src/routes/admin/*` author panel (guarded by `beforeLoad` for UX; every server function that touches private data uses `authMiddleware`)
- `src/features/entries/{server,shared}` server functions, DB queries, zod schemas, query options
- `src/features/auth` session helpers (`session.server.ts`: `readSession`, `requireUser`, `requireAuthor`), sign-in UI
- `src/features/social` likes and comments
- `PRODUCT.md` product truth; `.impeccable/` design contract and review captures
